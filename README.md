# Прокси-панель в Docker

Прокси — посредник: ваши программы выходят в интернет через другой сервер.
Эта панель ставит такой прокси на ваш компьютер и управляет им через браузер.
Всё работает в Docker, поэтому на систему ничего не устанавливается.

Подробности, безопасность и администрирование — в [docs/guide.md](docs/guide.md).

## 1. Что это

- Панель в браузере (`http://127.0.0.1:4050`): выбор сервера, установка, правила.
- Прокси на `127.0.0.1:7890`: сюда подключаются ваши программы.
- Серверы NL, USA1 и USA2 стоят за панелью; вы выбираете, через какой выход идти.

## 2. Что нужно

- Docker: Docker Desktop на Mac или Docker на Linux и WSL. Docker запускает программы в изолированных контейнерах.
- git: программа для скачивания проекта.
- Доступ к серверу: либо ключ для NL (для обнаружения входов), либо ссылки `vless://` от владельца (раздел 5).

## 3. Запуск за 3 шага

1. Скачайте проект:

   ```bash
   git clone <адрес-репозитория> mihomo-proxy-kit
   cd mihomo-proxy-kit
   ```

2. Запустите панель. Первый раз это долго: собирается образ.

   ```bash
   docker compose up -d --build
   ```

3. Получите ссылку входа и откройте её в браузере:

   ```bash
   docker compose exec kit kit token
   ```

Ссылка работает только на этом компьютере: адрес `127.0.0.1` означает «этот компьютер».
Сохраните её в закладки.

Чтобы терминал пользовался прокси, выполните в папке проекта `./proxy env on`, затем `source ~/.bashrc`
(для zsh — `source ~/.zshrc`). Отключить: `./proxy env off`. Команда меняет только свой блок в файле оболочки.
Подробности — в [docs/guide.md](docs/guide.md), раздел 8.

Команда `proxy` работает из любой папки. Один раз выполните `bash install-cli.sh`, затем, например, `proxy status`.
Подробности — в [docs/guide.md](docs/guide.md), раздел 10.

## 4. Первое подключение

Для шагов 2–4 нужен ключ NL. Задайте его в файле `.env` (см. [docs/guide.md](docs/guide.md)).

1. Откройте блок «Сервер NL». Впишите хост `<NL_IP>`, пользователь `root`, порт `22`. Нажмите «Сохранить».
2. Нажмите «Проверить ключ хоста». Откроется окно с отпечатками (строки `SHA256:…`).
   Сравните их с выводом `ssh-keygen -lF <NL_IP>` на своём компьютере. Совпали — нажмите «Подтвердить».
3. Нажмите «Обнаружить входы». Появятся карточки `USA1` (`<USA1_IP>`) и `USA2` (`<USA2_IP>`).
4. Откройте нужную карточку. У входа нажмите «Установить» и подтвердите. Следите за журналом задачи: статус станет «Готово».
5. Проверьте выход по адресу из раздела 7. Должен появиться IP выбранного сервера.

## 5. Простой режим: без доступа к серверу

Этот режим нужен, если владелец дал вам ссылки `vless://`. Ключ не нужен.

1. Вставьте ссылки в карточку «Импорт ссылок», по одной в строке.
2. Нажмите «Импортировать».
3. Откройте сервер в карточке «Серверы» и нажмите «Установить».

Новый импорт заменяет предыдущий список. Если хоть одна ссылка неверна, не сохраняется ничего.

## 6. Сайты и правила

Правила — во вкладке «Правила». Они проверяются сверху вниз, первое совпадение побеждает.

- `PROXY` — сайт открывается через сервер.
- `DIRECT` — сайт открывается напрямую, с вашего IP.
- `REJECT` — сайт не открывается.
- `MATCH` — что делать со всем остальным.
- Нажмите «Сохранить и применить», чтобы правила вступили в силу.

## 7. Проверка

```bash
curl --noproxy '' -fsS --max-time 20 -x http://127.0.0.1:7890 https://api.ipify.org
```

Команда спрашивает у сайта, с каким IP вы пришли, и идёт через ваш прокси.

- Вывод — IP выбранного сервера (например, `<USA2_IP>`): всё работает.
- Вывод — ваш обычный IP: прокси не используется. Проверьте установку и правила.
- Ошибка соединения: см. таблицу в разделе 8.

Программы подключаются к `127.0.0.1:7890` (HTTP или SOCKS5). Подробности — в guide.

## 8. Частые проблемы

| Что видно | Что делать |
|---|---|
| Панель: «Прокси-контейнер не работает» | Порт 7890 занят старой установкой на компьютере. Выполните переход со старой установки: [docs/guide.md](docs/guide.md), раздел 5. |
| Панель: «SSH-ключ не смонтирован» | Проверьте `KIT_SSH_KEY` в `.env`, затем `docker compose up -d`. Или используйте простой режим (раздел 5). |
| Панель не открывается | Выполните `docker compose ps`. Если `kit` не в состоянии `running`, выполните `./proxy logs kit`. |
| Ссылка входа потеряна | Выполните `docker compose exec kit kit token`. |
| Установка не удалась | Панель вернула прошлую рабочую конфигурацию. Прочитайте журнал задачи и проверьте ключ хоста. |

## 9. Обновление, остановка, удаление

- Обновить: `git pull`, затем `docker compose up -d --build`.
- Остановить, данные сохранятся: `docker compose down`.
- Удалить всё: `docker compose down -v`.

> **Внимание:** `down -v` удаляет базу, токен входа и подтверждённые ключи серверов (known_hosts).
> После него ссылку входа и ключи придётся получить заново.

## 10. Команды

| Команда | Что делает |
|---|---|
| `./proxy status` | состояние контейнеров и самой панели |
| `./proxy logs [kit\|proxy\|all] [-n N]` | последние строки журналов контейнеров |
| `./proxy check` | проверка входов NL из контейнера |
| `./proxy env on` / `off` / `status` | прокси в терминале: блок в `~/.bashrc` или `~/.zshrc` |
| `docker compose up -d --build` | запустить или пересобрать |
| `docker compose down` | остановить, данные сохранить |
| `docker compose exec kit kit token` | ссылка входа в панель |
| `docker compose ps` | состояние контейнеров |

Команды `./proxy server ...` нужны только владельцу серверов. См. раздел 6 в [docs/guide.md](docs/guide.md).
