# Прокси WSL → NL → USA (Docker)

Клиент работает в Docker: одна команда поднимает прокси и веб-интерфейс.
Приложения используют прокси на `127.0.0.1:7890`, настройка выполняется в браузере на `http://127.0.0.1:4050`.

## 1. Что это

```
приложения → 127.0.0.1:7890 (Mihomo, контейнер proxy) → Xray (тот же контейнер) → NL → USA1 / USA2
```

- контейнер `kit`: веб-интерфейс на `127.0.0.1:4050`, обнаружение входов NL, проверки, установка, правила;
- контейнер `proxy`: Mihomo на `127.0.0.1:7890` и локальный Xray на `127.0.0.1:18080` внутри контейнера;
- оба контейнера из одного образа, порты опубликованы только на loopback, Docker-сокет не монтируется.

## 2. Требования

- Docker Engine в WSL или Linux, либо Docker Desktop на macOS (Apple Silicon или Intel). Образ собирается под архитектуру машины (amd64 или arm64).
- Доступ в интернет к github.com и Docker Hub во время сборки.
- SSH-ключ с доступом root на NL.

## 3. Запуск

```bash
git clone <адрес-репозитория> mihomo-proxy-kit
cd mihomo-proxy-kit
cp docker/env.example .env        # по желанию; для обнаружения входов на NL задайте KIT_SSH_KEY
docker compose up -d --build
docker compose exec kit kit token    # ссылка входа
```

`KIT_SSH_KEY` нужен только для обнаружения входов на NL: путь к отдельному SSH-ключу только для NL, а не к основному ключу.
Без него панель работает в режиме импорта ссылок (см. раздел «Режим без доступа к NL»). Ключ монтируется в контейнер только для чтения.
Пример создания ключа: `ssh-keygen -t ed25519 -N '' -f ~/.ssh/nl_proxy -C "proxy-kit-$(hostname)"`.

Откройте ссылку входа. Она сохраняется в cookie, поэтому страницу можно добавить в закладки.

Готово считается, когда:
- `docker compose ps` показывает `kit` и `proxy` в состоянии `running`;
- `ss -ltn` показывает `127.0.0.1:4050` и `127.0.0.1:7890` и ничего на `0.0.0.0`;
- в интерфейсе видно состояние прокси без сообщения о занятом порту.

## Установка на новый компьютер

1. Требования: Docker Engine (Linux, WSL) или Docker Desktop (macOS, Apple Silicon или Intel); `git`; свой SSH-ключ, которым можно войти на NL.
2. Ключ для NL. Не копируйте приватный ключ с другой машины, создайте новый:

   ```bash
   ssh-keygen -t ed25519 -N '' -f ~/.ssh/nl_proxy -C "proxy-kit-$(hostname)"
   ssh-copy-id -i ~/.ssh/nl_proxy.pub root@<адрес-NL>
   ```

   Ключ без пароля: kit использует его без участия человека (BatchMode). Создавайте отдельный ключ только для этого NL-сервера и ограничьте его на NL (отдельный пользователь, при желании `from="<ваш IP>"` в `authorized_keys`).

   Если `ssh-copy-id` недоступен, добавьте содержимое `~/.ssh/nl_proxy.pub` в `/root/.ssh/authorized_keys` на NL вручную.
   Проверка: `ssh -i ~/.ssh/nl_proxy root@<адрес-NL> true` выполняется без запроса пароля.
3. Клонирование и `.env`:

   ```bash
   git clone <адрес-репозитория> mihomo-proxy-kit && cd mihomo-proxy-kit
   cp docker/env.example .env
   ```

   В `.env` задайте `KIT_SSH_KEY` для обнаружения входов: на macOS вида `/Users/<имя>/.ssh/nl_proxy`, на Linux и WSL вида `/home/<имя>/.ssh/nl_proxy`.
4. Запуск: `docker compose up -d --build`, затем `docker compose exec kit kit token` (ссылка входа).
   Интерфейс слушает только `127.0.0.1:4050`, поэтому открывать ссылку нужно на этой же машине.
5. Первая настройка в интерфейсе: NL, проверка ключа хоста, обнаружение входов, установка и проверка через curl. Подробно в разделах 4 и 5.
6. Если что-то не работает:
   - прокси-контейнер не работает: занят порт 7890, см. раздел 8;
   - ключ не смонтирован: проверьте `KIT_SSH_KEY` в `.env` и права файла;
   - `docker compose ps` должен показывать `kit` и `proxy` в состоянии `running`.

### Режим без доступа к NL (импорт ссылок)

Этот режим нужен, если у вас нет доступа к NL и SSH-ключа. Владелец выдаёт ссылки `vless://`, вы вставляете их в панель,
выбираете сервер и нажимаете «Установить». Ключ и настройки NL не нужны, шаг с ключом хоста пропускается.

Порядок для вас (второй участник):

1. `git clone <адрес-репозитория> mihomo-proxy-kit && cd mihomo-proxy-kit`
2. `docker compose up -d --build` (без `.env` и без `KIT_SSH_KEY` это работает: подключается пустой placeholder `docker/no-key`).
3. `docker compose exec kit kit token` и откройте ссылку входа на этой машине.
4. В карточке «Импорт ссылок» вставьте ссылки владельца, по одной в строке, и нажмите «Импортировать».
5. На вкладке «Серверы» выберите сервер, проверьте вход и нажмите «Установить».

Владелец выдаёт ссылки кнопкой «Показать ссылки» на своей панели. Ссылка в подписи содержит IP выхода (`NL -> <IP> ...`),
по нему панель понимает, куда ведёт вход. Если подписи нет, импорт отклонит ссылку и покажет номер строки.

Безопасность:
- каждая ссылка — секрет (uuid, pbk, sid). Она хранится в вашей базе (том `kit-data`) и видна только через ссылки сервера;
- ваша копия может использовать ссылку только как VPN-клиента NL, без SSH и без доступа к панели 3x-ui;
- отозвать доступ может только владелец: удалить или заменить uuid клиента в 3x-ui. После этого установка перестанет работать;
- тот, кто знает токен входа в панель, видит ссылки. Не передавайте токен.

Для владельца: обнаружение входов на NL (вкладка «Серверы» → «Обнаружить входы») требует `KIT_SSH_KEY` в `.env`.
Раньше ключ подключался неявно, теперь его нужно задать явно. Без него доступен только импорт ссылок.

## 4. Первая настройка

1. Вкладка **NL**: укажите хост NL, пользователя и порт SSH, нажмите «Сохранить».
2. «Проверить ключ хоста» покажет отпечатки ключа NL. Сравните их с `ssh-keygen -lF <хост>` на своей машине или с `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` на NL, затем нажмите «Подтвердить».
3. «Обнаружить входы» прочитает входы NL по SSH.
4. Вкладка **Входы**: выберите выход (USA1 или USA2), у входа нажмите «Проверить», затем «Установить».
   Установка рендерит конфигурацию, проверяет её (`xray run -test`, `mihomo -t`), применяет через контейнер `proxy` и проверяет выходной IP через прокси.
   При неудаче предыдущая рабочая конфигурация восстанавливается автоматически.
5. Вкладка **Прокси**: «Проверить прокси» должно показать IP выхода.

Проверка из терминала:

```bash
curl --noproxy '' -fsS --max-time 20 -x http://127.0.0.1:7890 https://api.ipify.org
```

Ожидаемый результат — IP выбранного выхода (для USA2 сейчас `149.28.240.154`).

## 5. Правила (сайты)

Вкладка **Правила**. Типы: `DOMAIN`, `DOMAIN-SUFFIX`, `DOMAIN-KEYWORD`, `GEOSITE`, `GEOIP`, `IP-CIDR`.
Политики: `PROXY` (через NL), `DIRECT` (напрямую), `REJECT`. Внизу задаётся `MATCH` (политика по умолчанию).
Служебное правило `DOMAIN,api.ipify.org,PROXY` всегда первое и нередактируемое: оно нужно для проверки выхода.
Правила по умолчанию: ChatGPT, Claude, Telegram через PROXY; российские домены, локальные адреса и `GEOIP,RU` напрямую.

«Сохранить и применить» пересоздаёт конфигурацию Mihomo. Если установлен вход, Xray не перезапускается.

## 6. Ссылки для телефона

Вкладка **Входы**, выберите выход и нажмите «Показать ссылки». Для каждого входа есть ссылка `vless://` (TCP+Vision, gRPC, XHTTP), кнопка «Копировать» и QR-код.

Ссылка — это ключ доступа. Не передавайте её посторонним. Ссылки показываются только по запросу и не сохраняются в браузере.

## 7. Как приложения используют прокси

- HTTP: `http://127.0.0.1:7890`; SOCKS5: `socks5://127.0.0.1:7890`.
- Переменные окружения для терминала (тот же блок, что ставил прежний установщик):

  ```bash
  export http_proxy=http://127.0.0.1:7890
  export https_proxy=http://127.0.0.1:7890
  export all_proxy=socks5://127.0.0.1:7890
  ```

- Для Claude Code, Codex и других CLI: `bash setup-ai-cli-proxy.sh`.
- Системный прокси macOS (не управляется проектом, выполнять вручную, сервис `Wi-Fi` замените своим):

  ```bash
  networksetup -setwebproxy "Wi-Fi" 127.0.0.1 7890
  networksetup -setsecurewebproxy "Wi-Fi" 127.0.0.1 7890
  networksetup -setsocksfirewallproxy "Wi-Fi" 127.0.0.1 7890
  # выключить:
  networksetup -setwebproxystate "Wi-Fi" off
  networksetup -setsecurewebproxystate "Wi-Fi" off
  networksetup -setsocksfirewallproxystate "Wi-Fi" off
  ```

- WSL: Windows-приложения достигают `127.0.0.1:7890` через переадресацию localhost WSL (включена по умолчанию).
- UDP через опубликованный порт не поддерживается (только TCP: HTTP и SOCKS5 CONNECT).

## 8. Переход с установки на хосте

Выполните до `docker compose up -d`: порт 7890 нельзя занимать двумя прокси. Проект сам ничего не останавливает.

Linux / WSL:

```bash
systemctl --user disable --now mihomo.service xray-mihomo.service xhttp-nl-admin-tunnel.service 2>/dev/null || true
crontab -l 2>/dev/null | grep -n mihomo || true   # строки mihomo-keepalive удалите вручную: crontab -e
ss -ltnp 'sport = :7890'                          # должно быть пусто
```

macOS:

```bash
for L in com.mihomo.proxy com.mihomo.xray; do
  launchctl bootout "gui/$(id -u)/$L" 2>/dev/null || true
  launchctl disable "gui/$(id -u)/$L"
done
lsof -nP -iTCP:7890 -sTCP:LISTEN                  # должно быть пусто
```

Старые файлы можно удалить вручную (проект их не трогает): `~/.local/bin/{mihomo,xray}`, `~/.config/mihomo/`,
`~/.config/systemd/user/{mihomo,xray-mihomo,xhttp-nl-admin-tunnel}.service`, `~/Library/LaunchAgents/com.mihomo.{proxy,xray}.plist`.
Строки `http_proxy` в оболочке продолжают работать: они указывают на `127.0.0.1:7890`.

Если UI показывает «Прокси-контейнер не работает», порт 7890 почти наверняка занят старой установкой. Выполните команды выше и затем `docker compose up -d`.

### Обновление: разделение тома kit-run

Раньше оба контейнера писали в один том `kit-run`. Теперь это два тома: `kit-gen` (конфигурации, пишет только `kit`,
`proxy` видит его только на чтение) и `kit-state` (статус, журналы, домашний каталог mihomo, пишет только `proxy`,
`kit` видит его только на чтение). Данные в `kit-run` можно пересоздать, поэтому миграция простая:

1. Остановите стек без `-v`: `docker compose down`. Флаг `-v` удалит `kit-data` (база, токен, known_hosts), этого делать нельзя.
2. Запустите стек: `docker compose up -d --build`. Появятся тома `mihomo-proxy-kit_kit-gen` и `mihomo-proxy-kit_kit-state`.
3. В интерфейсе снова нажмите «Установить» для входа, который был активен. До этого `proxy` в состоянии `idle`, порт 7890 закрыт.
   База, правила, токен и ключи хоста сохраняются.
4. Удалите старый том: `docker volume rm mihomo-proxy-kit_kit-run`. Если проект запускался с `-p <имя>`, том называется `<имя>_kit-run`.

## 9. Обновление и удаление

- Обновление: `git pull && docker compose up -d --build`.
- Остановка с сохранением данных: `docker compose down`.
- Полное удаление, включая базу, подтверждённые ключи хоста и конфигурации: `docker compose down -v`.

## 10. Администрирование серверов

Команды администратора серверов работают с `proxy.env` (только административные ключи, см. `proxy.env.example`). Клиент эти настройки не использует. Для установки сервера служит `bash server/setup-server.sh`.

### Команда proxy

Клиент работает только через Docker. Команды запускаются из корня проекта; ssh, `systemctl`, `launchctl` и файлы на хосте не используются:

- `./proxy status` — состояние контейнеров `kit` и `proxy` (`docker compose ps`) и состояние клиента (`kit status`).
- `./proxy logs [kit|proxy|all] [-n N]` — журналы контейнеров (`docker compose logs --tail N`), по умолчанию все.
- `./proxy check` — проверка входов NL из контейнера (`docker compose exec -T kit kit check`).

Администрирование серверов (NL, USA1, USA2) выполняется по ssh с адресами из `proxy.env`. Это только для администратора серверов, клиенту не нужно:

- `./proxy server status` — версия Xray и состояние службы на серверах.
- `./proxy server logs [nl|usa1|usa2|all] [-n N]` — журналы служб серверов в одном выводе.
- `./proxy server update ВЕРСИЯ [nl|usa1|usa2|all] [--yes]` — обновить Xray по одному серверу; после каждого проверка, при провале откат узла и остановка. Без `--yes` спрашивает подтверждение.

Команда `server update` ещё не запускалась на реальных серверах: сначала проверьте её на одном USA.

### Проверка соединения

```bash
docker compose ps
curl --noproxy '' -fsS --max-time 20 -x http://127.0.0.1:7890 https://api.ipify.org
```

## 11. Безопасность

- Порты опубликованы только на `127.0.0.1`. Доступ к UI имеет только тот, кто знает токен входа.
- Токен хранится в томе данных (`/data/ui-token`, 0600). Тот, у кого есть доступ к Docker, может прочитать его: это принятое ограничение.
- SSH-ключ монтируется только для чтения, копируется в tmpfs и никогда не попадает в образ, базу или ответы.
- Ключ хоста NL подтверждается вами: `StrictHostKeyChecking=yes`, `known_hosts` в томе данных.
- Контейнеры работают от uid 10001, без привилегий, с `read_only` корневой ФС и `no-new-privileges`. `kit` стартует от root только для копирования ключа, затем сбрасывает права.
- Ссылки `vless://` и база содержат секреты: не публикуйте том `kit-data` и ссылки.
- Тома разделены: `kit` и `proxy` видят том друг друга только на чтение. `kit` не может писать в `kit-state`, `proxy` не может писать в `kit-gen`.
