# Mihomo Proxy Kit: клиент → Netherlands → USA

Набор скриптов для двухзвенного прокси: клиент подключается к серверу в
Нидерландах, а тот пересылает трафик на выходной сервер в США. Сайты видят
американский IP, провайдер видит только соединение с Нидерландами.

```
телефон / ПК ──► NL 185.245.107.19 (3x-ui) ──► USA 1 108.61.222.91  ──► интернет
                                           └─► USA 2 149.28.240.154 ──► интернет
```

Храните репозиторий, `proxy.env`, `.env` и папку `servers/` в тайне: с этими
данными посторонний сможет пользоваться прокси и зайти в панель.

## Как это устроено

| Узел | Что работает | Чем управляется |
|---|---|---|
| NL `185.245.107.19` | Xray под управлением панели 3x-ui: принимает клиентов и выбирает выход | панель 3x-ui или `install-server.sh` |
| USA 1 `108.61.222.91` | отдельный Xray (вход на 443) + unbound | `/usr/local/etc/xray/config.json` |
| USA 2 `149.28.240.154` | отдельный Xray (вход на 443) + unbound | `/usr/local/etc/xray/config.json` |

Оба звена — VLESS + REALITY с SNI `dl.google.com`. На каждом USA-сервере один
клиентский ключ: им подключается NL. Имена сайтов резолвит unbound на самом
выходном сервере (`127.0.0.1:53`), резолверы хостера оставлены запасными.

### Входы на NL

| Порт | Транспорт | Клиент в панели | Выход |
|---|---|---|---|
| 2083 | XHTTP | `usa1-xhttp` | USA 1 |
| 2087 | XHTTP | `usa2-xhttp` | USA 2 |
| 443 | TCP + Vision | `main` | USA 1 |
| 443 | TCP + Vision | `server-2@install-server.local` | USA 2 |

Все входы используют одну пару ключей REALITY (`PUBLIC_KEY` в `proxy.env`).
У XHTTP-входов выход определяется портом, у входа 443 — клиентом.

### Какие ссылки использовать

- **XHTTP (порты 2083, 2087) — основные.** Весь трафик идёт по одному-двум
  долгим соединениям. Файл: `servers/vless-links-xhttp.txt`.
- **TCP на 443 — запасные и для локального Mihomo.** Новое соединение и новое
  рукопожатие на каждый запрос. Файл: `servers/vless-links.txt`.

Почему XHTTP: из домашней сети провайдер начинает отбрасывать подключения
VLESS + REALITY поверх обычного TCP после 15–30 рукопожатий подряд (обычный TLS
на тот же адрес при этом проходит). Пинг списка серверов или переключение
сервера в клиенте — как раз такая пачка. XHTTP рукопожатий почти не делает и
под этот фильтр не попадает. Прямые подключения к USA-серверам без NL режутся
так же, поэтому звено NL нужно.

## Панель 3x-ui

Панель слушает только `127.0.0.1` на NL и снаружи недоступна. Адрес, логин,
пароль и API-токен лежат в `servers/nl-3x-ui.env`.

1. Открыть туннель и оставить его висеть:
   ```
   ssh -N -L 46545:127.0.0.1:46545 root@185.245.107.19
   ```
2. Вывести адрес и учётные данные:
   ```
   ( . servers/nl-3x-ui.env; echo "http://127.0.0.1:46545/$XUI_WEB_BASE_PATH/"; echo "$XUI_USERNAME / $XUI_PASSWORD" )
   ```
3. Открыть адрес в браузере.

Где что в панели:

- **Inbounds** — входы и их клиенты. Чтобы выдать доступ ещё одному человеку,
  добавьте клиента в нужный XHTTP-вход: панель покажет ссылку и QR, маршрут
  менять не нужно.
- **Xray Configs** — шаблон конфигурации: исходящие подключения к USA
  (`to-usa`, `to-server-2`) и правила «вход → выход».

Любое изменение входов или шаблона перезапускает Xray на NL: соединения всех
клиентов обрываются на пару секунд.

### Чего не делать в панели

**Не обновляйте ядро Xray и саму 3x-ui кнопкой в интерфейсе.** Ядро панели
вручную заменено на Xray 26.3.27: комплектное 26.9.30 отклоняет подключения
клиентов Mihomo («REALITY authentication failed»). Комплектный бинарник
сохранён как `/usr/local/x-ui/bin/xray-linux-amd64.v26.9.30`. Перед любым
обновлением проверьте клиент Mihomo.

## Добавить новый выходной сервер

Нужен чистый сервер Ubuntu или Debian со свободным портом 443 и вашим
SSH-ключом для `root`.

1. Допишите адрес в `proxy.env` (номер — следующий свободный):
   ```
   SSH_TUNNEL_SERVER_3=root@НОВЫЙ_IP
   ```
2. Запустите:
   ```
   ./install-server.sh 3
   ```

Скрипт:

1. проверяет 3x-ui на NL и узнаёт версию его ядра Xray;
2. ставит на новый сервер Xray той же версии, генерирует ключи, поднимает
   вход на 443;
3. ставит и настраивает unbound;
4. через API 3x-ui добавляет на NL XHTTP-вход на свободном порту, исходящее
   подключение к новому серверу и маршрут;
5. проверяет с NL, что через новый вход внешний IP совпадает с новым сервером;
6. сохраняет ссылку в `servers/server-3/vless.txt` и дописывает её в
   `servers/vless-links-xhttp.txt`.

На новый сервер скрипт ходит по SSH через NL. Повторный запуск с тем же номером
безопасен: уже настроенное он не перезаписывает, ключ и порт остаются прежними.

Убрать сервер из панели:

```
./install-server.sh --remove 3
```

Удаляются вход, исходящее подключение и маршрут на NL и строка в общем списке
ссылок. Сам сервер, папка `servers/server-3` и строка в `proxy.env` остаются —
их удаляете вручную.

Детали поведения:

- **Порт входа** выбирается первым свободным из списка `XHTTP_PORTS` в начале
  скрипта (2083, 2087, 2096, 2053, 8443, …). Освободившийся после `--remove`
  порт будет занят следующим новым сервером.
- **Имена в панели** строятся от номера слота: клиент `usaN-xhttp`,
  исходящее `to-server-N`, название входа `USA N xhttp (IP)`.
- **Версия Xray** на новом сервере берётся с ядра NL, а не «последняя»:
  так оба конца REALITY остаются совместимыми.
- **Остатки в панели.** 3x-ui хранит клиента отдельно от входа и не удаляет
  его вместе с входом. Скрипт сам убирает такого «осиротевшего» клиента перед
  добавлением и при `--remove`; без этого панель отвечает
  `Duplicate email: usaN-xhttp`.
- **Права на конфиг.** `/usr/local/etc/xray/config.json` на новом сервере
  получает права `600`: в нём приватный ключ, а установщик Xray создаёт файл
  читаемым для всех.
- **Ошибки.** Скрипт печатает одну строку `Ошибка: …` и выходит с кодом 2;
  вывод удалённых команд с ключами в терминал не попадает. Если упало на шаге
  NL, сервер уже подготовлен — после устранения причины запустите ту же
  команду ещё раз.

Ограничения скрипта:

- для нового сервера создаётся только XHTTP-ссылка, отдельная ссылка на 443
  не делается;
- старые режимы `--resume` и `--recover` убраны: их заменяет повторный запуск
  с тем же номером.

## Локальный Mihomo (ПК, WSL, macOS)

`install.sh` ставит на компьютер Mihomo, который слушает `127.0.0.1:7890` и
ходит через NL по ссылке на 443:

```
./install.sh 108.61.222.91     # выход USA 1
./install.sh 149.28.240.154    # выход USA 2
```

Настройки берутся только из `proxy.env`. `unregister.sh` удаляет всё, что
поставил `install.sh`: сервис, автозапуск, переменные окружения, бинарник и
конфиг.

## Файлы

| Файл | Назначение |
|---|---|
| `proxy.env` | ключи входа NL и SSH-адреса серверов; образец — `proxy.env.example` |
| `install-server.sh` | подготовить выходной сервер и добавить его в 3x-ui; `--remove N` — убрать |
| `install.sh`, `unregister.sh` | поставить и удалить локальный Mihomo |
| `servers/vless-links-xhttp.txt` | основные ссылки (XHTTP) |
| `servers/vless-links.txt` | запасные ссылки (TCP, 443) |
| `servers/nl-3x-ui.env` | доступ к панели 3x-ui |
| `servers/server-N/` | параметры выходного сервера N и его ссылка |
| `incy-russia-direct-rest-proxy.json` | профиль маршрутизации для INCY: Россия напрямую, остальное через прокси |
| `backup.sh`, `restore.sh` | копия и восстановление конфига отдельного Xray на USA-сервере; для NL не подходят (см. ниже) |

Папки `servers/` и `backups/`, `proxy.env` и `.env` исключены из Git. В
`backups/` лежат старые копии конфигураций и настроек до перехода на 3x-ui.

## Диагностика

Команды для USA-серверов запускайте через NL: `ssh -J root@185.245.107.19 root@USA_IP`.

| Что проверить | Команда |
|---|---|
| Панель и Xray на NL работают | `ssh root@185.245.107.19 'systemctl is-active x-ui; ss -ltn \| grep -E ":(443\|2083\|2087) "'` |
| Ошибки панели и Xray на NL | `ssh root@185.245.107.19 'journalctl -u x-ui -n 50 --no-pager'` |
| Xray на выходе работает | `systemctl is-active xray; ss -ltn \| grep ":443 "` |
| Что проходит через выход | `journalctl -u xray -n 50 --no-pager` |
| unbound на выходе отвечает | `dig +short @127.0.0.1 www.google.com` |

Если у клиента серверы показывают `N/A` или подключение есть, а сайты не
открываются — сначала убедитесь, что используется XHTTP-ссылка, а не ссылка на
443, и переподключитесь: после перезапуска Xray на NL клиенту иногда нужно
подключиться заново.

Чтобы увидеть, кто и каким ключом подключается к NL, включите в панели в
**Xray Configs** журнал доступа (`log.access`), он пишется в
`/var/log/x-ui/access.log`. После диагностики выключите.

## Откат NL на отдельный Xray

Прежний Xray на NL остановлен и отключён, но не удалён; его конфиг — в
`/usr/local/etc/xray/config.json`.

```
ssh root@185.245.107.19 'systemctl disable --now x-ui; systemctl enable --now xray'
```

После отката работают только ссылки на 443 (и только те выходы, что были в
старом конфиге); XHTTP-ссылки перестанут работать, пока панель выключена.

## Известные ограничения

- `backup.sh nl` и `restore.sh` для NL работают со старым файлом конфигурации,
  а не с панелью. Копию настроек NL делайте в самой панели (Backup & Restore)
  или сохраняйте `/etc/x-ui/x-ui.db`.
- `backup.sh N` и `restore.sh` подключаются к USA-серверу напрямую, без NL.
  Если прямой SSH с вашей машины зависает, они не сработают.
- На USA 1 журнал Xray включён в режиме `debug` и растёт быстрее обычного.
- Скрипты рассчитаны на Debian и Ubuntu.
